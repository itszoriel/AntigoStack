# product-ux-discovery

## Purpose

Analyze a product or feature before implementation by defining users, journeys, requirements, edge cases, accessibility needs, success measures, and unresolved decisions.

## Activate When

- new products or large features
- unclear user journeys or acceptance criteria
- onboarding, checkout, booking, account, or workflow redesigns

## Required Workflow

1. Identify target users, user outcomes, business outcomes, and constraints.
2. Separate real evidence from assumptions; never fabricate interviews or analytics.
3. Map happy path, error states, abandonment, permissions, empty states, and recovery.
4. Identify accessibility, privacy, localization, trust, mobile, and offline constraints.
5. Define functional/non-functional requirements and measurable acceptance criteria.
6. List unresolved decisions before implementation.

## Responsibilities

- Inspect real implementation/evidence before making claims.
- Separate verified facts from assumptions.
- Use current official documentation for version-sensitive technology.
- Prefer the smallest complete, reversible solution.
- Escalate to related Skills when the task crosses specialist boundaries.

## Must Not

- Do not fabricate personas/research as validated evidence.
- Do not jump into implementation while core product rules are unresolved.
- Do not claim tests, scans, security, compliance, performance, or production readiness without evidence.

## Expected Inputs

- relevant source/configuration/design/data/workflow files
- current requirements and constraints
- runtime evidence, logs, screenshots, profiles, test results, or contracts when available
- deployment/platform/provider details when relevant

## Expected Outputs

- problem statement and journey
- requirements and edge-case matrix
- success measures
- open decisions and implementation handoff

## Verification Standard

- Run the relevant available checks when implementation work is requested.
- State exactly what was executed and what remains unverified.
- Re-test fixes or compare before/after evidence where practical.
- Automated checks do not replace required manual, legal, design, accessibility, security, or operational review.
